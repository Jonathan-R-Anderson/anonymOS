Node releases

← Admin

These are the binaries /network hands out. They are not in the container image — six platforms is ~180 MB that would ride in every deploy on a node that has already had its images garbage collected by disk pressure — so they are uploaded here once per release and stored in the object store, keyed by hash.

Build them with storage-client/scripts/build-release.sh, then upload each file from storage-client/dist/. The platform you pick and the file's own executable header have to agree — an upload under the wrong platform is refused rather than published, because the consequence of getting it wrong lands on someone else's machine days later.

For the Linux builds, prefer ./scripts/publish-node-release.sh on the server: it builds, writes the checksums and publishes all of them in one pass, taking the platform from the filename instead of from a dropdown next to a file picker. Those are the ones curl -fsSL https://dendritic.network/install.sh | sh fetches from /dl/<binary>, so a Linux platform left unpublished here is an installer that 404s on somebody's machine. This form stays for macOS and Windows, and for a one-off fix.

Applied to every upload below. The toolchain is published so somebody who rebuilds from source knows which compiler produces a matching hash.
