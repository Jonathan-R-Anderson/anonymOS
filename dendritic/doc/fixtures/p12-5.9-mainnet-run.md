Retrieval is not a trust shortcut: `EvidenceStore.Get` re-runs the whole proof
chain before returning, so a DHT holder cannot alter what a record says.

## Defects this run exposed — none findable synthetically

1. **Wrong fork indices.** Mainnet is on Fulu; `finality_branch` is depth 7, not
   Altair's 6. `IndicesFor` refused rather than verifying against the wrong
   field. Fixed with `FINALIZED_ROOT_GINDEX_ELECTRA = 169`, committees 86/87,
   **taken from consensus-specs v1.6.1**, not inferred from the observed depths.
2. **Wrong signing domain.** The domain was built from the genesis fork version
   `0x00000000`; Fulu is `0x06000000`. Every real signature would have failed.
   The fork version is now selected **at the signature slot**, as the spec's
   `*_at_slot` functions do. Synthetic tests missed this because they used one
   arbitrary version consistently on both sides.
3. **The decoder discarded the execution payload.** The real `LightClientHeader`
   carries `beacon` + `execution` + `execution_branch`; the last two were being
   dropped, removing the only link from consensus to the execution state root.

## The trap that nearly passed as success

An earlier run printed "REAL FINALITY applied / trust level: finalized". It was
**not** verification: the update's finalised slot equalled the bootstrap's, so
`ApplyFinalityUpdate` took the idempotent path with **zero BLS calls**, and
`TrustLevelOf` was comparing the finalised header against itself.

Only instrumenting the production verifier to COUNT calls exposed it. A nil
error is not evidence that a signature was checked.
