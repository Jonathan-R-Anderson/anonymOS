# IMMUTABLE_ROOTLESS §F on an INSTALLED system — the 4/4 case.
#
# tests/immutable-rootless.txt asserts what a LIVE-MEDIA boot reports, where the object store
# deliberately stays in RAM because the disk is reserved for the installer, so IMMUTABLE-1's
# backing-on-disk=0 is the correct answer there and the honest summary is 3/4.
#
# This suite asserts the other case: a disk-backed store, where all four immutable conditions hold.
# Verified 2026-09-07 — the summary line below was produced by a real boot, not predicted.
#
# TO RUN IT, give the store a disk to mount (the store claims the free tail after the last
# partition; a bare GPT is enough):
#
#     sgdisk --clear --new=1:2048:+512M --typecode=1:EF00 hos-disk.img
#     TIMEOUT=260 scripts/boot-test.sh tests/immutable-installed.txt
#     cp /tmp/hos-disk.backup.img hos-disk.img     # restore the blank fixture afterwards
#
# The restore matters: leaving the disk partitioned changes what every other suite measures.

require  [objstore] installed system (GPT)
require  [F]     immutable-1 parts: usr-write-refused=1 usr-readable=1 verity-verifies=1 backing-on-disk=1
require  [F] IMMUTABLE-1 system-tree-read-only-and-verified  PASS
require  [F] IMMUTABLE-2 state-split-enforced  PASS
require  [F] IMMUTABLE-3 atomic-update-and-rollback  PASS
require  [F] IMMUTABLE-4 no-w-xor-x-pages  PASS

# The whole §F bar, both halves, in one line.
require  [F] SUMMARY immutable 4/4 -> IMMUTABLE;  rootless 4/4 -> ROOTLESS

forbid   EARLY BOOT EXCEPTION
